# Atlas 9.0 — Hosted AI (no Mac installation)

Atlas is hosted on GitHub Pages; API keys cannot safely be placed into its public browser JavaScript. This repository contains **atlas-hosted-worker.js**, a private backend intended for Cloudflare Workers. Once deployed, Atlas can run from Mac, iPhone or any internet-connected device without Ollama, Python, or Tailscale.

## Fastest way: Deploy to Cloudflare

Open [Deploy Atlas AI to Cloudflare](https://deploy.workers.cloudflare.com/?url=https://github.com/jackdelenbaas-sys/atlas-ai/tree/main/cloudflare-worker), sign in to Cloudflare/GitHub, and follow the deployment steps. The isolated cloudflare-worker directory contains the complete app server. The deployment still requires two private secrets: **OPENAI_API_KEY** and **ATLAS_ACCESS_TOKEN**. Once deployed, copy the resulting workers.dev HTTPS URL into Atlas Settings.

## Manual cloud setup (alternative)

1. Sign in at https://dash.cloudflare.com/ and go to **Workers & Pages → Create Worker**. Choose a name such as **atlas-ai-private**.
2. Open the Worker's **Edit code** page. Replace the initial code with the contents of **atlas-hosted-worker.js** in your GitHub repository. Save and deploy.
3. In the Worker dashboard, open **Settings → Variables and Secrets**. Add two values of type **Secret**:
   - **OPENAI_API_KEY**: your OpenAI Platform key, from https://platform.openai.com/api-keys .
   - **ATLAS_ACCESS_TOKEN**: a new, random 32+ character token, preferably generated by a password manager. Do not reuse the OpenAI key.
   Save and deploy the secrets.
4. Copy your Worker URL, for example https://atlas-ai-private.your-identity.workers.dev . Do not append a path.
5. Open https://jackdelenbaas-sys.github.io/atlas-ai/?v=91 , go to **Settings → Atlas Cloud AI** and paste the Worker URL and private Atlas access token. Click **Save connection and test live AI**.

Never put either secret in GitHub code or chat. Atlas saves only its server URL in browser localStorage, and saves the access token temporarily in sessionStorage. The real OpenAI key stays server-side in Cloudflare.

## Current capabilities and limits

- Chat with web search and citations, image understanding, image generation, avatar actions, and video-generation API support subject to account permissions.
- Attach images, PDFs, plain text and code. Videos are analyzed using sampled still frames only.
- DOCX, XLSX, and PPTX are currently **not extracted by the hosted backend**; don't assume the AI has read those files.
- Conversation history and user memory remain stored only in that browser and are **not synced** across devices.
- API usage (including search, images, and video) is billed separately from ChatGPT subscriptions. Set spending limits on your API project.
- Keep the strong access token private. The Worker is a private single-user gateway, not a full user-account and sign-in service.

## Troubleshooting

- HTTP 401: The Atlas access token is missing or incorrect.
- HTTP 503: The Worker secrets aren't configured or the access token is too short.
- HTTP 502 with upstream OpenAI 401/403: OpenAI key or project permission issue.
- HTTP 502 with upstream OpenAI 400: An unsupported model, tool, or request.
- HTTP 429: API rate or spending limit.
- Browser network error: Check the Worker URL and that its deployment is active.

No Mac-side setup is needed after the Worker is deployed.
