# Atlas — Free daily chat and images

Atlas uses Cloudflare Workers AI through the AI binding in wrangler.jsonc. No OpenAI key is used. Optional free-plan Groq and Gemini connections can supplement Cloudflare.

Keep the Cloudflare Workers account on the Free plan. The free allocation is account-wide, shared by chat, image understanding and image generation, and resets at midnight UTC. Image requests consume more of that allowance. Workers Paid accounts can bill overage.

Required runtime binding: AI (Workers AI). Required runtime secret: ATLAS_ACCESS_TOKEN, matching Atlas Settings. Existing configured tokens are preserved on deployment.

Supported: text chat, text attachments, JPEG/PNG/WebP image understanding with Llama 4 Scout, and new images and direct reference-image editing with FLUX.2 Klein 4B. Uploaded images are resized in the browser; up to three attachments per message. Images can be displayed in the studio, downloaded, pasted or dropped, and retained in this browser through IndexedDB.

Edit image attaches the selected original for direct editing. Follow-up instructions such as “make it green” automatically use the latest image in the current conversation. Reference images are resized below 512 pixels to meet the model input limit. The model can still change unintended details; pixel-perfect preservation is not guaranteed. No live web image search, PDF understanding or video generation is enabled.

Studio buttons control gestures and walking without using AI quota. Each answer runs a short context-matched gesture sequence; new requests and Stop cancel it. Natural movement adds occasional idle variations and respects reduced-motion preferences. Uploaded and generated images appear on the studio screen automatically.

Daily-limit errors include the next UTC reset; requests work again when the provider resets its quota. The connection test also consumes a small amount of the same allowance.

Atlas defaults to a brief, warm, witty and lightly sarcastic voice. Sass softens for serious topics and can be adjusted by saying “less sarcasm” or “more sass.” Familiarity grows from a local interaction counter and explicit saved preferences, not invented memories. No separate personality or memory AI calls are made. Browser memory stores at most 80 notes, selects up to eight within 1,100 characters for a request, and sends bounded recent conversation history. Say “remember that …”, “what do you remember”, or “forget …” to manage notes. Clearing all memory also resets familiarity. Default chat output is capped at 320 tokens; requests for detailed explanations, drafts or code can use 900 tokens.

Studio controls now start collapsed in a native expandable menu; Escape or clicking outside closes it. Generic dance requests shuffle the hosted dance library, avoid the previous routine when another is available, and retain fallback clips if a download fails. Named dance requests retain their specific style. Replies are rendered before motion starts; a new command cancels a pending action. Stop remains available in the controls while AI is busy. Failed requests restore the original draft and attachments when they would not overwrite newer input. Animation metadata is separated from visible chat text.

## Optional free-plan backups

Text routing: Groq, then Gemini, then Cloudflare. Uploaded-photo understanding: Gemini, then Cloudflare. Image creation and editing remain on Cloudflare. This reserves more Cloudflare neurons for images; it does not increase Cloudflare’s account-wide allowance. Multiple keys for one account do not add quota.

Create a free Groq account/key at https://console.groq.com/keys and keep it on the Free plan. Add runtime secret GROQ_API_KEY and runtime text variable GROQ_FREE_PLAN=true to the existing Worker, then deploy. Gemini is optional: create a key in a free project with billing disabled at https://aistudio.google.com/apikey, then add GEMINI_API_KEY and GEMINI_FREE_PLAN=true. Never paste keys in chat, the frontend, or a public repository. The flags are owner attestations, not verification of billing status; do not enable them for paid accounts. No key alone activates a backup.

Backup failures fall through once to the next enabled provider; content-policy refusals do not. Each provider has its own limits and reset schedule. Connection status reports configured credentials, not a live quota balance or successful inference; Test connection runs a small inference through the available chain. Groq uses openai/gpt-oss-20b hosted by Groq, not OpenAI's API. Gemini uses gemini-3.5-flash-lite for text and photo understanding, not image generation. Current free-tier terms may allow provider use of submitted data; review provider terms before sending sensitive content.

No dependable free recurring video-generation API was verified. Video requests return an explicit unavailable error without calling chat or a paid generator. Hugging Face currently provides no free-user inference credits; Pollinations free rewards are quest-based, not automatic daily refills. Neither is enabled as a paid fallback.

## Live web photos and factual sources

“Show me photos of cows” searches Wikimedia Commons and returns up to six real photos, each with its source and license. It does not call image generation or consume AI neurons. “Create an image of a cow” uses generation. Retrieved photos can be displayed in the studio or opened in the image editor. The server loads only JPEG/PNG/WebP bytes from upload.wikimedia.org or thumb.wikimedia.org, blocks redirects, and enforces a four-megabyte limit. Thumbnails load from Wikimedia; original source pages document licensing.

Factual questions retrieve fresh Wikipedia extracts before asking AI to summarize. The answer includes the actual retrieved source URLs. No results or retrieval failure is reported explicitly; it is never labeled successful web research. This is scoped live retrieval from Wikipedia and Wikimedia, not general Google/Brave web search, and it cannot verify real-time weather, breaking news, prices or every website. No paid search API is used. Uploaded-image questions go to an actual vision model and follow-ups about the current image can reattach its pixels.

Edit image now opens a preview and change-instructions form. Apply edit sends the selected original and instructions to the image-editing endpoint; it no longer merely changes the composer. Image generation quota still applies. Exact preservation of unedited details is not guaranteed by the model.

Photo replies use an unboxed preview strip and a short caption. New web photo results start a studio slideshow, advancing every 5.5 seconds. Images are downloaded once per slideshow and reused without AI calls. Only the first frame adjusts the camera; later frames preserve the user's view. Selecting another image or conversation cancels the slideshow. Photo credits are accessible in a collapsed Settings section rather than inline citations. Generated-image actions are under Image options.


### Studio controls (10.9)
New chats and switching conversations clear and hide the presentation, cancel slideshow loads and queued actions, and restore the avatar/camera. No previous picture is restored automatically. Common screen/camera requests run locally without inference. The AI receives bounded current scene state and can return validated commands for screen content, visibility, position, size, rotation; camera presets/angles/zoom; avatar movement/position; slideshow selection; room visibility and idle motion. Commands execute after the reply paints, with failures reported instead of success claims. This controls the Atlas studio, not the browser or operating system. Shared command contract: atlas-studio-controls.mjs.

### Photo playback fix (10.10)
Photo replies automatically start the studio slideshow. Downloads use browser CORS first, with the private Worker proxy as a fallback; broken downloads are skipped without interrupting working photos. "Put them on the screen" restarts the conversation's photo slideshow. Searches use exact subject phrases, relevance ranking from titles/descriptions/categories, unrelated-subject filtering and duplicate-view removal. Modern-house requests also search contemporary houses and modern villas; no filler photos are added just to reach six. Metadata filtering cannot guarantee the visual style of every source photo.

### All-subject relevance and dated photos
All photo searches require each meaningful requested term (or a bounded synonym) to match source metadata using whole words. Requests can exclude subjects with "without" or "not". Real-photo requests reject known synthetic images, illustrations and unwanted toy/statue substitutes. Each search retrieves live source metadata; no stored result list is reused. Explicit recent/new/current requests require an original capture date within the last 365 days; today/this week/this month/this year narrow that window. Upload timestamps do not qualify. Missing, invalid, old and future dates are excluded. Returned metadata records capture date when available and retrieval time. No unrelated filler is added. These are source metadata checks, not visual authentication; a recent capture does not establish that a product is its latest model or that a historical claim is current.

### Normal view, fitting and calm responses (10.12)
Recent original capture dates (last 365 days) are the default for photo searches. Explicit historical/archive requests can opt out. Fresh searches inspect more candidates sorted by recent edits, then separately validate original capture dates; an edit/upload date never qualifies a photo as recent.
Normal view in Studio controls and "return to normal" restore default screen size and Atlas/camera layout while keeping photos. Portrait and landscape photos get an aspect-matched screen and a thin physical frame. Camera fitting includes the whole screen and avatar with space reserved for the composer, reruns after screen resize/window resize, and transitions over 550ms. No image cropping is used.
Response gestures use one gesture followed by idle. Replaying an active clip preserves animation phase. Response sequences no longer walk Atlas home or restart idle at completion; expressive Happy Idle changes are removed from automatic idle selection. Natural breathing/blinking remain. "Make me a pic" routes to actual image generation instead of generic chat.

### Viewer facing and persistent screen-off (10.13)
Chat interaction requests a smooth whole-body turn toward the camera. Return to Center in Settings and the center camera control request the same orientation after walking completes. Explicit avatar rotation remains authoritative until another conversation interaction.
Screen Off sets a visibility latch, invalidates image decodes and notifies the slideshow to cancel its timer and pending download. A normal slideshow tick cannot override Off. Explicitly presenting photos again starts a new presentation.
Natural idle selection no longer swaps a running idle clip, and asynchronous idle loads must still match the current conversation-action generation before playing. Animation fade state is reset before a reused action starts. This addresses late arm pose changes without disabling requested movements.

### Prefer recent, always allow a relevant fallback (10.14)
This supersedes the hard capture-date cutoff above. Photo searches prefer the newest relevant candidates using original capture dates when available; otherwise upload time is a discovery-ranking signal, not a claimed capture date. Matching undated or older photos remain eligible instead of causing an empty result. Subject/synthetic-image filters remain. Replies simply say "Here it is" or "Here are the photos"; date-check explanations are removed. One-picture requests return one result. Conversational filler is ignored; "Tesla robot taxi, the new one" resolves to Cybercab, and "cyber truck" resolves to Cybertruck. Tesla's official support confirms the Cybercab Robotaxi naming: https://www.tesla.com/support/robotaxi/cybercab .

### Retrying image retrieval and conversational corrections (10.15)
Photo searches clean retry chatter, normalize compound spacing, preserve real search names (Paris/Texas are not stemmed in outgoing queries), and use separate recent/relevance Commons searches. Clear title matches rank before recency so new incidental mentions cannot outrank the requested subject. Photo requests reject document/music scans, charts and known synthetic/illustrated substitutes; undersized photos are skipped when dimensions are known. Singular requests return one photo.
If Commons has no suitable image, Wikipedia lead images and their original file metadata are retrieved. If both lookups fail, one small free-plan inference may rewrite the query with recent conversation context, followed by up to three actual search retries. Only retrieved file URLs can be returned; the rewrite cannot supply an image URL or a success claim. Source availability and daily free limits can still prevent retrieval.
A noun-phrase correction after a failed photo request continues image search instead of generic chat. A named photo request "on the screen" searches for that subject rather than trying to show an empty gallery. If a model requests showing photos but the studio is empty, the server retrieves a real image first instead of returning a promise plus an empty show command.
Validated live downloads for Cybercab spacing/corrections, golden retriever, Paris, red panda, Mount Fuji and sushi. Image URLs, bytes and a diagnostic contact sheet were checked.
